
### LINUX SYSTEM ADMINISTRATION.

- Manages and maintains linux-based computer systems, installing and configuring software, managing user accounts and permissions, system backup etc.

## Linux File System Structure.

#### 1. Linux Filesystem structure - identify key folders and what their role and importance.

Linux uses a single-root hierachical filesystem, everything starting from / (the root directory)

1. `dev` - contains device files that represent hardware components.
E.g harddrives, terminals, printers : acts as interface between h/w ans s/w.

2. `mnt` - temporary mount points for administrators. Its always empty , you use it when you want to mannually mount something.

3. `proc` - its a virtual filesystem that contains information about the running process with a specific process ID . Contains virtual files with info about cpu info, memory usage, process details..

4. `sbin` - contains system administration commands e.g reboot.

5. `tmp` - contains temporary files created by users and applications. Its contents are deleted automatically upon reboot.

6. `vmlinuz` - virtual memory linux gzip. A compressed linux kernel image for booting the linux OS.

7. `bin` - contains executable programs e.g ls,bash,cat.

8. `etc` - contains the system configuration files and settings (password).

9. `lost+found` - used to find recovered bits of corrupted files, stores a recoverd file after a filesystem check.

10. `opt` - reserved for installation of optional , third party software packages.

11. `root` - the home directory of the root user . (/) is the root of the entire filesystem tree, accesssible only by the root.

12. `srv` - stores data for services offered by your system e.g webpages, Ftp downloads.

13. `usr` - contains themajority of user-related programs , libraries, documentation and shared data. E.g /usr/bin

14. `boot` - contains files required for the system to boot.

15. `home` - contains the personal directory for each user where they store their personal files, documents, etc.

16. `lib` - contains shared libraries that are essential for programs and system binaries to run. Without lib commands like ls cannot run.

17. `media` - a directory for automatically mounted removable media. E.g usb drives, CDs

18. `run` - used to store runtime data for processes  (information the system need for the system is running)

19. `sys` - virtual filesystem created by the Linux kernel to expose information about devices , drives, and the kernel itself (contains h/w and kernel informaion in a structured way).


20. `var` - stores variable datafiles that are expected to change frequently during system operations. E.g /var/log for system logs.

21. `wget-log` - a file log generated by wget command.

#### 3. What are groups? What are their benefits?
- ***Groups***-  is a collection of users that share permissions, access rights to files , directories and other resources.
  - primary group - default group assigned to a user when their account is created.
  - secondary group - additional groups a user can belong to.
      group info: cat/etc/group - group_name:password_placeholder:GID:user_list
##### Benefits of groups
1. Easier permission management - instead of assigning permission to individual users , admin can set permissions for an entire group.

2. Security - only the group members can access the files.

3. Collaboration - groups enables multiple users to work on shared projects and access common resorces effeciently.

#### 5. What are logs? Where are they located? How are they beneficial? At the end of this module, identify 3 different logs that are helpful for a Linux System Admin to periodically monitor.

-**Log** is a file to capture real-time information about activities. Its a record of events generatedby the system : what happened, where and when.

**Location**: `/var/log`

##### Benefits:
1. Troubleshooting - it helps identify why a service failed or crashed.

2. Security monitoring - administrators can track unauthorised access or suspicious activity e.g authlogs

3. Performance monitoring - helps check system performance and health.

4. Preventive maintenance - helps detect issues before they cause downtime.

5. It helps keep a record of who did what and when.

#### Types of logs

1. `sys.log` - records everything happening on your system . Contains system messages, network issues, system warnings, errors from backround programs.

2. `auth.log` - records all login attempts and sudo activity. contains: successful logins, failed logins, sudo commands run, password failures.
Helps to detect hacking, track who used sudo, investigate unauthorized access.

3. `kern.log` - records messages from the linux kernel. contains: h/w errors, driver issues, memory error. The importance is : helps detect h/w failures, kernel crashes, device driver problem.

4. `boot.log` - shows what happens when the system is starting up. Helps you to see the services starting, services failing , boot errors.

5. `dpkg` - records every s/w installed or removed using Apt. Tracks: what was installed, when it was installed, whether the installation failed.

6. `cron.log `- shows the schedules and results of all automated tasks. Importance: check if backups ran, to see if scheduled scripts failed , troubleshoot automated tasks.

7. `fail2ban` - shows attempts to break into your system through SSH or other services. Contains: ips blocked, repeated login attempts

8. `user.log` - contains applications started by users and errors from user-level programs.

9. `ufw.log` - useful for checking firewall activity. Records everything events and activity related to the uncomplicated firewall. Provides details on hich network packets are being blocked or allowed by the firewall rules.

10. `Xorg`- contains screen resolution issue. contains messages from the xorg server , responsible for managing graphical display.

11. `btmp `- shows usernames and ips of failed logins.

12. `wtmp` - shows all logins and logouts.

13. `faillog` - contains summaries of failed logins.

14. `alternative.log` - records the history of all changes made by the update-alternatives command. Manages like which python, editor /java to use.

15. `dmesg`- shows messages from the kernel during boot. It shows which h/w was detected , missing drivers, Disk/USB detection.

**Output explanation:**

- PID: Shows task’s unique process id.
- USER: User name of owner of task.
- PR: The process’s priority. The lower the number, the higher the priority.
- NI: Represents a Nice Value of task. A Negative nice value implies higher priority, and positive Nice value means lower priority.
- VIRT: Total virtual memory used by the task.
- RES: How much physical RAM the process is using, measured in kilobytes.
- SHR: Represents the Shared Memory size (kb) used by a task.
- %CPU: Represents the CPU usage.
- %MEM: Shows the Memory usage of task.
- TIME+: CPU Time, the same as ‘TIME’, but reflecting more granularity through hundredths of a second.
- COMMAND: The name of the command that started the process.

`top - 11:54:43 up  2:10,  1 user,  load average: 0.46, 0.28, 0.27`

  - System Time: The current time on the system.
  - Uptime: How long the system has been running since the last boot.
  - Users: The number of users currently logged into the system.
  - Load Average: Shows the average number of processes waiting for resources. This is shown in three numbers separated by commas. These numbers represent the average number of processes waiting for CPU time over the last 1 minute, 5 minutes, and 15 minutes, respectively. A value of 1.0 means the system's CPU is fully utilized; higher values indicate potential overloading.

`Tasks: 297 total,   3 running, 294 sleeping,   0 stopped,   0 zombie`

  - total: Indicates the total count of processes currently being tracked/managed by the system.
  - running: Represents the number of processes currently actively using CPU time.
  - sleeping: Refers to processes that are currently idle and waiting for a signal to wake up.
  - stopped: Denotes processes that have been manually stopped, typically through a signal.
  - zombie: Indicates processes that have completed execution but still have an entry in the process table.

`%Cpu(s):  0.4 us,  0.1 sy,  0.0 ni, 99.5 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st `

  - us: Percentage of CPU time spent running user processes.
  - sy: Percentage of CPU time spent running kernel (system) processes.
  - ni: Percentage of CPU time spent running processes with a nice value (priority adjusted).
  - id: Percentage of CPU time spent idle (no work being done).
  - wa: Percentage of CPU time spent waiting for I/O operations to complete.
  - hi: Percentage of CPU time spent servicing hardware interrupts.
  - si: Percentage of CPU time spent servicing software interrupts.
  - st: Percentage of CPU time stolen from this virtual machine by the hypervisor (if virtualized).

`MiB Mem :   7597.5 total,   1276.2 free,   4432.6 used,   2717.5 buff/cache`
  - total: Total amount of physical memory (RAM) available in MiB.
  - used: Amount of RAM currently in use by processes and the kernel.
  - free: Amount of RAM not being used at all.
  - buff/cache: Amount of memory used for buffering data and caching filesystems.

`MiB Swap:    977.0 total,    977.0 free,      0.0 used.   3164.9 avail Mem`
  - total: Total amount of swap space available in MiB.
  - used: Amount of swap space currently in use.
  - free: Amount of swap space that is not being used.
  - available: Estimate of how much memory is available for starting new applications without swapping.

- `top -u (username)` - shows processes for a specific user : example top -u lwachira.
- `top -p (PID)` - shows for a specific process id.
- `top -o %MEM` - Sorts in memory usage.
- `top -o %CPU` - Sorts in CPU time.

**7. `Kill`** - used to send signals to processes for managing their execution. Signals e.g pause, continue, terminate.
- importance:
  - To stop misbehaving processes.
  - To shut down services.
  - To forcefully terminate unresponsive applications.
  - To reload configuration files.
  - To manage jobs and background tasks.

- `Kill -l` - lists all signals.

   1. `SIGTERM` - Signal number (`15`) this is the default signal, sent to allow it to terminate gracefully, allowing it to shut down properly.
      - kill -SIGTERM <PID>
      - kill -15 <PID>
      - kill <PID>
  2. `SIGKILL`- Signal number (`9`)used to force kill a stuck process.
     - kill -9 <PID>
     - kill -SIGKILL <PID>
  3. `SIGSTOP` - Signal number (`19`) to pause a running process without terminating it.
     - kill -STOP <PID> 
  4. `SIGCONT` - Signal number (`18`) To resume a paused process.
     - kill -CONT <PID>
  5. `SIGHUP` - used to reload configuration files(hang up).
  6. `SIGINT` - used to interrupt a process.
  7. `SIGQUIT` - used to quit a process.


**8. `pkill`** - stands for process kill, this is a way to kill processes by name or other attributes such as username or terminal.

   E.g 
   -  pkill firefox
       -  pkill -9 firefox - it is used to force kill firefox.
       -  pkill -u lwachira - kills all processes under the user lwachira
       -  pkill -u lwachira firefox - kills firefox opened by user lwachira only.

- Difference btwn pkill and kill : kill sends signals to processes by PID, pkill sends signals to processes by name or attribute.

   - Syntax: `ln -s original_file softlink_file` example: `ln -s trial.txt trial_softlink.txt`

 - components: 1. Type : deb - are ready to install software. deb-src - contains the source code packages.
2.Repository URL -where the system will fetch the packages from .
3.Distribution/release name - tells apt which version of packages to download e.g bookworm -Debian 12, trixie -Debin 13
4.Components/sections -main contains free software, non -free -firmware a section of firmware that is not free.

11. How does one update and upgrade a Debian Linux PC? What are the different options of updating and upgrading? Update and upgrade your PC by simply executing the commands (NB: Do NOT edit or alter any source files for this task)
   - using the sudo apt update - this refreshes the package list to know which packages have the latest versions.
   - sudo apt upgrade - this installs the latest version of all currently installed packages.
   - sudo apt full-upgrade - upgrades packages including dependacies.

12. Relevant questions:
 - What is nginx?  - is a web server, a program that listens for requests from browsers and sends back websites or data.

 - Why is the purpose of the folder you created under /var/www...? - its called the web root folder, where you put your website files.

 - What do the two folders sites-enabled and sites-available help accomplish? - sites-available stores all the nginx server block. it's like a library of all possible websites you want to serve. Files here are not automatically active, Nginx wont automatically serve them until you enable them. Sites-enabled this folder contains symbolic links (shortcuts) to the files in the sites-available.

 - What is a symlink? - its like a shortcut or pointer to another file.

 - What is the hosts file used for? Name at least 2 uses. - host file is a local file that maps hostname to ip address.

 - What is the difference between service and systemctl? -systemctl is a tool used to control systemd used to start,stop,restart,reload a service. service is an older method to run basic commands like start, stop, restart a service.

 - What is the difference between restart and reload with the context of a service? restart a service stops the service completely then starts it again. reload tells the service to re-read its configuration files without stopping the entire service.

 - If we edit the index.html and add some content, do we need to restart, reload anything or do something else to view the changes.  - just save the changes then on the browser refresh it.
